# MoonRead

Stardust-themed private web reader for verified Thai Markdown chapters generated by the Novel workspace.

Brand palette:

- Navy: `#121926`
- Gold: `#EBC05F`
- Logo text/cream: `#F0F0F0`

## Local Workflow

Run from this directory:

```powershell
npm.cmd ci --ignore-scripts --no-audit --no-fund
npm.cmd run dev -- --hostname 127.0.0.1
```

The versioned `content/generated/` snapshot is enough to develop and verify the UI. Do not regenerate it for UI-only changes. `generate:chapters` reads the local translated output configured in `../00_Config/novel_registry.json` when preparing a separately approved content update.

Current catalog covers and decorative search images use pre-sized WebP assets. When replacing a PNG source used by the catalog, update its counterpart in `public/images/reader/` so browsing stays independent of on-demand image conversion.

The reader supports configured chapter ranges per book. Missing chapters are shown as unavailable until the source Markdown exists and passes validation.

Reading position, chapter bookmarks, favorites, and reading settings are saved in the current browser, not an account. A bookmark added from the reader remembers the passage; older and chapter-list bookmarks open at the chapter start. If a book has a different saved reading position, even in the same chapter, the bookmark opens in labeled review mode until you choose to save your place there. With no conflicting saved position, opening a bookmark starts a normal reading session. Clearing website data removes saved state.

Chapter links keep their original route IDs even when the published title prints a different number. The displayed episode number and numeric search use the title's number where available. Catalog and chapter search can submit before JavaScript is ready. Navigation inside the reader fetches the next chapter's data before replacing the visible passage; a failed request leaves the current chapter and any open chapter search in place with a retry action.

## Validation

`npm.cmd run generate:chapters` rejects chapters with:

- missing H1 title
- empty or too-short content
- bad encoding markers
- unintended Chinese body text
- provider/meta leakage

Rejected chapters are not linked in the reader UI. See `content/generated/import-report.md` after generation.

## Vercel

Use the existing GitHub-Vercel connection and import this repository with:

- Root Directory: `MoonRead`
- Framework Preset: `Next.js`
- Install Command: `npm install`
- Build Command: `npm run build`

No API keys or provider credentials are required for the reader web.

If the repository is a monorepo, make sure Vercel points to `MoonRead`, not a novel folder.

Vercel does not need access to novel `05_Output` folders. Commit `content/generated/` after running `npm.cmd run generate:chapters` locally, then Vercel builds from that generated reader content.

## GitHub

Commit the `MoonRead/` directory plus generated reader content when you want Vercel to deploy the latest readable chapters.

Do not commit:

- Vercel tokens
- provider API keys
- `.vercel/`
- `node_modules/`
- `.next/`

## Updating Chapters

After another translation run updates `05_Output`, regenerate and rebuild:

```powershell
npm.cmd run generate:chapters
npm.cmd run build
```

Then commit the changed `MoonRead/content/generated/` files and push to GitHub. Vercel will deploy from GitHub after the push.

## Verification

```powershell
npm.cmd run lint
npm.cmd audit --omit=dev
npx.cmd playwright install chromium
npm.cmd run build
npm.cmd run test:reader
npm.cmd run smoke
```

`test:reader` and `smoke` use temporary local Next.js servers and fresh Playwright Chromium contexts, with no signed-in browser profile. `smoke` writes screenshots and a JSON result; set `MOONREAD_SMOKE_OUTPUT_DIR` to a task-owned directory outside the checkout.

For cross-engine checks install the Playwright engine (`npx.cmd playwright install firefox webkit`) and set `MOONREAD_BROWSER` to `firefox` or `webkit` for `test:reader`. These are engine checks, not physical-device tests.
